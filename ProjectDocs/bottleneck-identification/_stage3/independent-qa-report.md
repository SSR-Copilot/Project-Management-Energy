## Answers to the priority questions

**1. Behaviour regressions (hand-merged files).**
- `data/costBook.ts`: `chunk` and `eq` are genuinely unused now (the only remaining text matches are comments); `ACTIVE`, `and`, `idIn`, `lookupEq`, `lookupIn`, `money`, `numberOf` are all still used. The four `readChunked` sites keep per-chunk filters, selects and `.flat()` order. The milestone-duration code moved byte for byte to `data/milestoneDurations.ts`; no importer of the old location remains (src, e2e, scripts).
- `features/pm/revenues/hooks.ts`, `finance/hooks.ts`, the three `queries.ts`: every hook is `{ ...factory, enabled }` with the old `enabled` expression; keys unchanged (`qk.revenues`, `qk.revenuesReference`, `qk.financeReference`, `qk.production`); `REFERENCE` is applied to the same reads that had `staleTime: 30 min`. Finance's `refetchOnMount: "always"` reads (D109) are correctly not prefetched; UT-BOOT-SCREENS-205 pins it.
- `useCostBook.ts`: key construction (including the `"opex"` suffix), `everyVisit`, `scope`, `onContracts`, `loadStates`, pending-delete exclusion are all in `costBookQueryOptions` unchanged. `useCapexComments`'s `keepPrevious` is opt-in (CAPEX grid only), the one-contract panel keeps the old behaviour (UT-CAPEXCOM-020/021).
- `pmScreenPrefetch.ts` and the repointed mocks: every `vi.mock` of a moved function now targets the module the code imports (`projectStatesRead`, `revenueLookups`, `currencies`, `milestoneDurations`); no stale mock of `generalData.listProjectStates`, `revenues.findCurrency` or `costBook.loadMilestoneDurations` remains. `findCurrency` without `onlyThisCode` now calls `loadAllCurrencies()` directly, which is exactly what `landLease.loadCurrencies()` wrapped.
- Import moves: `textFormat` / `forLanguage` come from `@/domain/powerFxNumeric`, which the Generators `rulesCore` re-exported, so the functions are identical.

**2. Prefetch correctness.**
- Key and function equality holds by construction (shared factories) and is exercised with the REAL hooks in UT-BOOT-COST-001/002/003 and UT-BOOT-SCREENS-200..206 (each read counted once, none after the mount). I checked the screen call sites: CAPEX `useCostBook(category)` / `useCapexTotals(isSummaryTab)`, OPEX `useCostBook(undefined, {everyVisit, scope:"opex"})`, Land Lease `useLeaseAssumptions(extras.countryId, extras.technology)` all match the prefetch arguments.
- No key with `refetchOnMount: "always"` is prefetched: Contracts rows, payment targets, DevCo links (`REREAD_ON_VISIT`), the OPEX book (`everyVisit`), `opex-device-types`, and Finance's project/inputs/repayments/step-ups are excluded. The two DevCo keys that ARE prefetched have the default 30 s stale time on the screen.
- Switches: `costReads` OFF -> `await session; return` (old); `pmExtraScreens` OFF -> the three new prefetchers return before any import; `adminChunk` OFF -> no loader; `intentChunks` and `intentData` both OFF -> no listener and no dynamic import. `INTENT_PREFETCH_DATA` defaults to false, chunks to true (`entryPrefetchFlags.ts`).
- Authorisation: prefetches run under the signed-in user's own Dataverse rights and only for a project id that `readProjectLink` validated as a GUID; nothing renders from the cache until the route gate passes. Admin chunks are downloaded for a hover or deep link whether or not the user is an admin (chunk bytes only, no data).
- Boot target category: `categoryFromSearch` accepts 0..99 while the screen clamps to the real tab count; an out-of-range N costs one wasted book read (documented).

**3. Read lane.** Result order preserved (`Promise.all` over the gate wrapper); first failure in time wins; a queued chunk is skipped after a sibling failure (the `failed` flag) and cannot cause an unhandled rejection (`Promise.all` attaches to every promise). No deadlock: every `read` callback at the 18 sites is a bare `fetchAll`; no callback awaits another lane task, and the paired `readChunked` calls (`landLease`, `opexCatalog`, `costBook` payments + comments via `onContracts`) run side by side, not nested. Starvation and hung-slot risk: see F3.

**4. Cache tier.** `REFERENCE` is imported by no Cost module (`UT-QPOL-004`, and my grep agrees), so the cost book, totals, Add Cost sheet and the D51 patching of an unmounted book keep the global 5-minute gc. Memory held longer: only small fixed-key lists (countries, project states, areas, utilizations, finance pickers, per-country Fabric rows). Has-contracts opt-out: only the focus refetch is off; mount refetch past 30 s stays. Residual: a check that FAILED is no longer retried on focus (Retry button and remount still work), and a contract booked by a colleague is not seen until remount; Delete re-checks on the server.

**5. Module moves.** No circular import found (the closure script and the allow-list test agree; `costQueries.ts` -> `costBook` / `pendingDeletes` / `projectStates` / `comments`, never back). `vi.mock` seams were repointed as above. Side effects: none lost (the moved modules had no top-level effects). The allow-list hides 32 existing data -> features value edges by design (they are the heavy rules files, e.g. `data/revenues -> features/pm/revenues/rules`); it does not hide new ones, and the "light module must not reach heavy" tests cover only the named pairs (UT-IMPGRAPH-002..006), so a new heavy edge from, say, `milestoneDurations` into `costBook`'s feature rules is caught while one from `revenueLookups` into `data/finance` is not.

**6. Test quality.** UT-ADCHK-902: see F4 (assertion legitimately replaced, one gap). Other changed tests only repoint mocks/imports; the bench pins (`PINNED` in `checklistVisit.bench.test.tsx`) are additions. `UT-BOOT-SCREENS-020`, `UT-BOOT-010` were reworded for the new flags and still assert the old behaviour with the switch OFF. `bootPrefetch.test.ts` / `bootPrefetch.screenReads.test.ts` now turn the new switches OFF, so the defaults ON are covered only by the new files; acceptable. New tests (readChunks differential, wave tests, key-equality with real hooks, trace-once with 10 re-renders, unload-prompt hold/release) assert real behaviour. Wave tests are a model: the "before" case replays the same prefetchers after a simulated 2-wave gate, so they prove the ordering claim, not Dataverse latency.
