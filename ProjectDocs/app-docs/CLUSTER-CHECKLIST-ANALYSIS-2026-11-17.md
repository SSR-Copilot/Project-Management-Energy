# Cluster Checklist screen: functional, non-functional and UI analysis (17 Nov 2026)

**Screen:** PM "Project General CheckList Screen" (Edit Project module), code app `ProjectCosts-CodeApp/src/features/pm/checklist/` (`Screen.tsx`, `rules.ts`, `hooks.ts`, `ProjectStates.tsx`) and `src/data/checklist.ts`. Canvas: `Project General CheckList Screen.pa.yaml`.
**Branch:** `sub/cluster-checklist-analysis` from `RounakDev1` at `b0258ee`. **Type:** analysis only, no code changed. **Not run:** the screen was not exercised on DEV or in a browser; every statement comes from reading code, the canvas YAML and test output.
**Principle applied (product owner):** the code app need not translate the YAML literally; its utility, function, non-functional quality and UI must be the same or better. A difference is reported only if a user would get a different result, message, permission outcome, enabled state or data, or a worse experience.
**How:** five read-only reviews (load and display, writes and workflows, non-functional, UI and accessibility, test audit). Status words: **CHECKED** = the lead read the code; **REPORTED** = a review's finding, not re-checked; **COMPUTED** = a number the review calculated (for example a contrast ratio); **DERIVED** = request counts worked out from the code, not measured.
Findings already recorded in D29, D66, D81, D105 and D106 are not repeated.

## 2. Smaller issues (reported unless stated)
