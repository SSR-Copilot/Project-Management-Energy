### 2.2 Loading and perceived performance

- **Two spinners** (geometry and copy in `06-POPUPS.md` §2.7):
  - the text-less content-area spinner `spn_LoadingSpinnerCost` (`locIsVisibleLoadingCostSpinner`), used for navigation, reloads and delete;
  - the modal card `cmp_Costs_PopUpLoading` (`locIsVisiblePopUpSpinner`), used for saves, paid toggles, standard contracts and comments.
- **Timers used as UX workarounds.** Bodies are in `07-…`:
  - `tmr_Capex_Initial_Load`: 500 ms, repeating, waits for the App.OnStart collections (L778-787);
  - `tmr_Capex_Cost_Category_SwitchTabs`: 300 ms, `AutoStart: =locStartCategoryBinding` (L18928-18933);
  - `tmr_Capex_Cost_Category_SwitchTabs_1`: 100 ms, `AutoStart: =locStartCategoryBinding1` (L19032-19037);
  - both tab timers are disarmed by the tab `OnSelect`, which sets both flags `false` (L2441-2446);
  - `tmr_Capex_Cost_Cost_EnrichLoader`: 100 ms, `AutoStart: =locStartBinding`, prefetches the panel's totals (L19136-19160);
  - `tmr_Load_Contract_Gallery_Warmup`: 1 ms, `AutoStart: =locWarmupKick`. This defers building the year gallery by one tick so the panel paints first, and gates it with `locPanelReady` (L19580-19738, L12551).
- **Hidden code buttons run as subroutines through `Select(...)`:**
  - `btn_Capex_Cost_Reload_PCF_After_Mutation_Code` (L722-777), which re-reads `CAPEX Project Contracts` and `CAPEX Costs` for the whole project after every mutation, with the content spinner up;
  - `btn_Capex_Cost_Refresh_Capex_Cost_Code` (L1014+);
  - `btn_Capex_Cost_Build_StandardContractOptions_Code` (L452+).

### 2.5 Empty and error states

- **No category selected.** The grid area is `Visible: =Not(IsBlank(tab_….Selected.'CAPEX Account List'))` (L2536). The Summary gallery shows instead (`con_Costs_ContentCostsSummary`, L7769).
- **Category with no accounts after filtering.** The PCF draws a spinning **"Loading data…"** placeholder (`GridRenderer.ts` `renderEmptyState`, vendored at `GridRenderer.js:1427-1437`). It never resolves, because "empty" is drawn as "loading".
- **Load failure.** Nothing handles it. `OnVisible` and the initial-load timer read with no `IfError`. A failed or empty read leaves the poll waiting and the spinner up (inferred from L782).
- **Write failures.** Notifies N3-N8 (`06-POPUPS.md` §2.9).

### 2.6 Unsaved-change and discard guards

There are none.
- **Panel ✕ and Cancel** reset every field and close the panel at once (L10330-10353, L18175-18199).
- **The panel scrim** `con_cost_RightPanel_Form_AddContract` (full width, `Fill: =RGBA(0, 0, 0, 0.3)`, L10249-10264) has no `OnSelect`. Clicking outside the panel therefore does nothing, and the left navigation underneath it cannot be reached while the panel is open (inferred).
- **Comments ✕** clears `colCapexComments` and `colDeletedComments` (L8237-8240).
- **Leaving the app.** Closing or reloading the browser tab drops edits with no prompt.

### 2.7 Focus, keyboard and tab order

- **No control on the screen sets `TabIndex`** (grep, 0 hits), so tab order follows the control tree.
- **One `SetFocus`:** `btn_Capex_Comment_Save.OnSelect` begins `SetFocus(btn_Capex_Comment_Save)` (L10137), which commits the in-progress text input.
- **No `OnHidden`.**
- **App Checker** findings for this screen (`AppCheckerResult.sarif`, by `ruleId`):
  - **90** `acc-AccessibleLabelNeeded`;
  - **51** `acc-TabIndexShouldBeDefinedForInteractiveControl`;
  - **6** `acc-FocusBorderShouldBeVisible` (for example `Label1` in the comments header, and the Link to Cluster asterisk).
- **Grid keyboard support** (vendored from the PCF source `GridRenderer.ts`):
  - month cells with a cost are `tabIndex=0`, `role="button"`, and open their menu on Enter or Space (`GridRenderer.js:965-982`);
  - the toggle, ••• and Add buttons are native `<button>`s;
  - menus close on an outside click (`ActionDropdown.js:52-55`). There is no Escape handling and no arrow-key navigation in any PCF menu (grep).

### 2.8 Scroll and responsive behaviour

- **The app is responsive, not scaled.** `DocumentLayoutScaleToFit: false`, `DocumentLayoutMaintainAspectRatio: false`, authored at 1366 × 768 landscape (`Properties.json:96-101`).
- **Grid area:**

### 3.2 Loading and perceived performance

- The inline loader is shown only on a cold query (`Screen.tsx:301`); the Summary tab's totals have their own inline loader (`:692`).
- The blocking overlay covers mutations (`:1045-1049`).
- There are no timers. Data comes from TanStack queries with session caching. The cost book is per category; categories, project states and milestone durations have a 30-minute `staleTime` (`useCostBook.ts:523`, `:542`, `:561`).
- The PCF repaints without rebuilding rows on resize (`PcfGrid.tsx:52-61`).

### 3.6 Unsaved-change and discard guards

### 3.7 Focus and keyboard

- **The panel** is a Fluent overlay `Drawer`: it traps focus, closes on Escape, and returns focus on close (Fluent default, inferred).
- **Dialogs** are Fluent `Dialog modalType="alert"`: they trap focus, cancel on Escape, and ignore backdrop clicks (`ConfirmDialog.tsx:355-359`).
- **Tab order** is DOM order. No `tabIndex` or `autoFocus` is set in `Screen.tsx` (grep). The only `tabIndex` values are the PCF's month cells and comment dots (`GridRenderer.js:967`, `:1017`).
- **The tab strip** is a set of `<button role="tab">` inside `role="tablist" aria-label="CAPEX categories"` (`Screen.tsx:683-689`). Every tab is a separate Tab stop, with no roving `tabIndex` and no arrow-key handler (inferred from the absence of handlers).
- **The year rows** are `<button aria-expanded>` (`Screen.tsx:910-919`).
- **After a mutation**, the PCF host re-renders its DOM (`PcfGrid.tsx:64-68`). Focus on the triggering grid button is lost, and nothing restores it (inferred).

### 3.8 Scroll and responsive behaviour

- `.canvas-cost-screen { flex: 1; display: flex; flex-direction: column; min-height: 0; overflow: hidden }` (`canvas.css:176`).
- The tabs and the toolbar each have `overflow-x: auto` (`:177`, `:190`).
- `.canvas-pcf-host { flex: 1; min-height: 300px; overflow: hidden }` (`:212`). The renderer scrolls inside and gets `allocatedWidth` from `clientWidth` through a `ResizeObserver` (`PcfGrid.tsx:74-90`).
